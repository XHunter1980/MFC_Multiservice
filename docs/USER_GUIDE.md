# Руководство пользователя — «МФК Мультисервис» v9.6

Инструментарий для **параллельной работы с множеством МФК** (многопользовательских контроллеров) по сети SSH/TCP: массовое обновление прошивок и конфигураций, проверки состояния, сбор информации, загрузка файлов и выполнение консольных команд на десятках устройств одновременно.

- **Разработчик:** Екимов Д.А., компания «ИскраТехно» (iskratechno.ru)
- **Платформа:** Windows 10/11 x64 (портативный EXE) либо Python 3.10+ (запуск исходника)

---

## 1. Установка

### Вариант А: готовый EXE (рекомендуется)
1. Откройте страницу релизов репозитория: `Releases` → выберите последний тег (например, `v9.6`).
2. Скачайте `MFC_Multiservice_v9.6.exe` (или ZIP-архив) и поместите в любую папку. Установка не требуется — приложение портативное.

### Вариант Б: запуск из исходников
```bash
pip install -r requirements.txt
python MFC_Multiservice_9.6.py
```

Требуемые зависимости: `tkinter` (входит в стандартную поставку Python), `pandas`, `openpyxl`, `paramiko`, `xlsxwriter`.

---

## 2. Подготовка файла со списком устройств

Приложение читает список устройств из **Excel-файла** (пример — `Стенд_103_v2.xlsx` в корне репозитория). Файл обязан содержать колонки:

| Колонка | Назначение |
|---|---|
| `IP` | IP-адрес устройства (проверяется доступность по порту TCP/22) |
| `Login` | Имя пользователя SSH |
| `Password` | Пароль SSH (числовые пароли автоматически преобразуются в строку) |
| `ENABLE` | Флаг активности: устройство берётся в работу, если значение `+`, `Y`, `YES`, `TRUE` или `1` |
| `NAME` | Имя/название устройства (отображается в интерфейсе и логах) |
| `ARH` | Признак архитектуры устройства (используется при валидации группы; устройства ALT_SP обрабатываются с увеличенным таймаутом) |
| `Model` | Модель устройства |

После загрузки открывается **диалог выбора устройств** — можно отметить/снять отдельные устройства или выбрать/снять все. Выбранные устройства становятся рабочей группой для всех операций.

## 3. Интерфейс программы

Окно состоит из:
- **«Список устройств»** — путь к Excel-файлу, кнопки `Обзор` и `Выбрать`;
- **Вкладки**: `Обновление`, `Операции`, `Команды`, `Настройки`, `О программе`;
- **«Прогресс»** — индикатор выполнения и текущая операция;
- **«Журнал операций»** — цветной лог (ошибки — красным, успех — зелёным, предупреждения — оранжевым); кнопка `Сброс и очистка` очищает журнал;
- Метка **«ТЕСТОВЫЙ РЕЖИМ!»** появляется внизу, когда включён dry-run.

Все настройки сохраняются между запусками в файл `updater_settings.json` рядом с программой.

### 3.1 Вкладка «Обновление»
- Чекбоксы типов обновления: **Прошивка**, **Конфигурация**, **Target2**;
- Пути: директория прошивки, XML-файл конфигурации, XML-файл target2;
- Кнопки:
  - **Выполнить обновления** — запускает параллельное обновление выбранных устройств (до 10 потоков, до 3 попыток на устройство). Целевая версия прошивки читается из файла `version_dev.txt` в директории прошивки;
  - **Остановить** — корректно прерывает процесс (устройства, где обновление уже идёт, завершают текущую операцию);
  - **Перезагрузить** — перезагрузка выбранных устройств по SSH.

> Перед стартом выполняется валидация: выбраны ли устройства, существуют ли файлы, совпадает ли архитектура в группе. При смешанной архитектуре программа предупредит и предложит уточнить выбор.

### 3.2 Вкладка «Операции»
- **Проверить устройства** — пинг/проверка доступности SSH (порт 22, таймаут 10 с); недоступные помечаются в журнале;
- **Проверить прошивки** — сравнение текущих версий ППО на устройствах с целевой (из `version_dev.txt`); результат выводится с цветовым кодированием версий;
- **Проверить конфиги** — сравнение версий конфигураций с выбранным XML-файлом;
- **Собрать информацию** — опрос параметров каждого устройства и сохранение результатов (отчёт в локальную директорию);
- **Проверить дубликаты MAC** — поиск одинаковых MAC-адресов среди устройств (конфликты в сети);
- **Загрузка файлов на устройства** — укажите локальную директорию и удалённый путь (например `/tmp/`; история путей сохраняется через кнопку `+`). Файлы загружаются по SFTP с созданием недостающих каталогов и проверкой целостности (размер/контроль после записи). Кнопка `Остановить` прерывает загрузку.

### 3.3 Вкладка «Команды»
- Поле **Консольная команда** с историей (кнопка `+` добавляет текущую команду в историю);
- **Суперпользователь** + поле пароля SU — если нужно выполнить команду с повышенными правами (`su`);
- **Послать консольную команду** — параллельная отправка команды на все выбранные устройства, ответы выводятся в журнал;
- **Рестарт ППО** — типовая операция перезапуска подсистемы ППО на группе устройств.

### 3.4 Вкладка «Настройки»
| Опция | Описание |
|---|---|
| Проверять версию прошивки / конфига | Включают соответствующие проверки перед обновлением |
| **Тестовый режим (dry-run)** | Операции имитируются без реальных изменений на устройствах; в интерфейсе горит метка «ТЕСТОВЫЙ РЕЖИМ!» |
| Вести лог | Запись в файл журнала (ротация: 10 МБ × 3 резервных копии) |
| Перезагружать устройства | Автоматическая перезагрузка после успешного обновления |
| Директория логов | Куда складывать файлы журнала и собранные отчёты |

## 4. Типовой рабочий сценарий

1. `Обзор` → выбрать Excel-файл со стендом → отметить нужные устройства в диалоге.
2. Вкладка **Операции** → `Проверить устройства` — убедиться, что все доступны.
3. Вкладка **Обновление** → указать директорию прошивки (с `version_dev.txt`), файл конфигурации; отметить нужные типы обновлений.
4. Для страховки включить **Тестовый режим** (Настройки) и выполнить `Выполнить обновления` — проверить план действий в журнале.
5. Выключить тестовый режим → `Выполнить обновления`. Следить за прогрессом и журналом; при необходимости — `Остановить`.
6. После обновления: `Проверить прошивки` / `Проверить конфиги` для контроля результата; при необходимости `Перезагрузить`.

---

## 5. Журналирование и отказоустойчивость

- Все операции пишутся в ротационный лог-файл и одновременно в окно «Журнал операций».
- Каждая сетевая операция повторяется до **3 раз** с нарастающим таймаутом; проблемное устройство можно пропустить (**Skip device**) без остановки всей группы.
- Устройства семейства **ALT_SP** обрабатываются по отдельному пути с увеличенным таймаутом (30 с).

## 6. Часто задаваемые вопросы

**«Файл Excel должен содержать колонки …»** — проверьте заголовки листов: имена регистрозависимы (`IP`, `Login`, `Password`, `ENABLE`, `NAME`, `ARH`, `Model`).

**Устройство всегда недоступно** — убедитесь, что на нём включён SSH-сервер (порт 22) и нет блокировки брандмауэром; попробуйте `Проверить устройства` ещё раз.

**Нужно обновить только часть стенда** — снимите лишние устройства в диалоге «Выбрать» или обнулите флаг `ENABLE` в Excel.

## 7. Сборка приложения из исходников (для разработчиков)

Windows EXE собирается PyInstaller с использованием иконки `multiservise.ico`:

```bash
pip install -r requirements.txt pyinstaller
pyinstaller build.spec --noconfirm
# Результат: dist\MFC_Multiservice_v<версия>.exe (onefile, windowed, иконка .ico)
```

Версия в имени EXE берётся из `version.py` (`APP_VERSION`).

## 8. Релизный процесс (автоматизация)

- **Автотесты** (`tests/test_mfc_multiservice.py`, pytest) запускаются GitHub Actions на каждый push/PR в `main` (workflow `.github/workflows/test.yml`).
- **Релиз**: при изменении версии в исходнике (`UpdaterApp.VERSION_INFO`) необходимо:
  1. обновить `APP_VERSION` в `version.py`;
  2. создать и запушить тег `v<версия>` (например `git tag v9.6 && git push origin v9.6`).
  
  Workflow `.github/workflows/release.yml` сверит тег ↔ `version.py` ↔ `VERSION_INFO` исходника, прогонит тесты, соберёт EXE на windows-latest (иконка — `multiservise.ico`) и опубликует GitHub Release с EXE и ZIP-архивом. Версия релиза всегда равна версии исходника; при расхождении сборка останавливается.
