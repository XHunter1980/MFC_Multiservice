# МФК Мультисервис (MFC Multiservice) v9.6

Настольное GUI-приложение (Tkinter) для массового управления, обновления и мониторинга сетевых устройств (включая специализированную платформу ALT_SP). Автоматизирует полный цикл администрирования парка устройств: от проверки доступности и сверки версий до обновления прошивок, конфигураций и удаленного выполнения команд.

**Связь с устройством:**  
SSH/SFTP (`paramiko`) — выполнение команд, загрузка файлов и управление конфигурациями. Для устройств ALT_SP реализована автоматическая эскалация привилегий через `su` с увеличенным таймаутом ожидания.

## Основные возможности

| Операция | Описание |
| --- | --- |
| **Обновление прошивки** | Загрузка `.img`, `RemoteInstallServer` и `update.stu` на устройство, запуск скрипта обновления с контролем версий (опционально). |
| **Обновление конфигурации** | Замена `config.xml` с предварительной сверкой описания (`<Global description>`) и размера файла. Автоматическое создание резервной копии (`config_old.xml`). |
| **Обновление Target2** | Замена `target2.xml` с резервным копированием существующего файла. |
| **Проверка устройств** | Массовая проверка доступности выбранных устройств по SSH (порт 22). |
| **Сбор информации** | Выгрузка версии ОС, прошивки, описания конфигурации и MAC-адресов со всех устройств с сохранением в Excel (`device_info_*.xlsx`). |
| **Проверка дубликатов MAC** | Анализ собранных данных и формирование отчета о конфликтах MAC-адресов (`mac_duplicates_report_*.xlsx`). |
| **Загрузка файлов** | Массовая загрузка файлов/директорий с рекурсивным созданием путей, переименованием существующих файлов (суффикс `.old_дата_время`) и проверкой целостности по размеру. |
| **Консольные команды** | Отправка произвольных команд на выбранные устройства с поддержкой режима суперпользователя (`su`). |
| **Рестарт ППО** | Специализированная операция для безопасного перезапуска служб `PrjA-tele` и `PrjA` через `systemctl`. |
| **Тестовый режим (Dry Run)** | Имитация всех операций без реального изменения устройств (для безопасной проверки сценариев). |

## Требования

- Python 3.8+
- Зависимости: `pandas`, `paramiko`, `openpyxl` (см. `requirements.txt`)
- Сетевой доступ к устройствам по SSH с правами пользователя, указанного в Excel-файле.

## Установка и запуск

git clone https://github.com/XHunter1980/MFC_Multiservice.git
cd MFC_Multiservice

# Создание и активация виртуального окружения
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt

# Запуск приложения
python MFC_Multiservice_9.6.py

Для сборки исполняемого файла (.exe):
pip install pyinstaller
pyinstaller build.spec

(Собранный файл будет размещен в директории dist/)
Конфигурация
Параметры интерфейса и пути сохраняются в файле updater_settings.json, который создается рядом с запускаемым файлом:
Ключ
Описание
excel_path
Путь к последнему использованному файлу Excel со списком устройств
firmware_dir
Директория с файлами прошивки (.img, RemoteInstallServer, update.stu)
config_file
Путь к локальному файлу конфигурации (.xml)
target_file
Путь к локальному файлу target2.xml
log_enabled
Флаг включения записи журнала операций в файл
log_dir
Директория для сохранения файлов логов (с ротацией, макс. 10 МБ, 3备份)
dry_run
Флаг «Тестовый режим» (по умолчанию false)
reboot_devices
Автоматически перезагружать устройства после успешного обновления
upload_dir / remote_path
Локальная директория и удаленный путь для массовой загрузки файлов
use_su / su_password
Использование режима суперпользователя и пароль для su (критично для ALT_SP)
⚠️ Внимание: Файл updater_settings.json может содержать пароли в открытом виде и не должен попадать в репозиторий (он добавлен в .gitignore).
Архитектура кода (один файл)
Приложение реализовано в виде единого модуля для удобства развертывания:
UpdaterApp — основной класс GUI (Tkinter), управление вкладками, очередью логов и состоянием.
ProgressTracker — потокобезопасный счетчик прогресса с блокировкой (threading.Lock).
ThreadPoolExecutor — параллельное выполнение операций на нескольких устройствах одновременно (до 10 воркеров).
Интеграция с paramiko для SSH/SFTP операций с автоматическими повторными попытками (retry_attempts = 3) и увеличенным таймаутом для устройств ALT_SP.
Рабочий процесс (типовой цикл)
Подготовка Excel: Создать файл с колонками IP, Login, Password, ENABLE, NAME, ARH, Model.
Загрузка: Нажать «Обзор», выбрать файл, отметить нужные устройства в диалоговом окне.
Настройка: На вкладке «Обновление» выбрать типы обновлений (Прошивка, Конфигурация, Target2) и указать пути к файлам.
Проверка: Включить «Тестовый режим» на вкладке «Настройки» для безопасного прогона.
Выполнение: Нажать «Выполнить обновления». Приложение автоматически проверит версии, загрузит файлы и применит их.
Завершение: При необходимости нажать «Перезагрузить» для применения изменений на устройствах.
Разработка и CI/CD
Тестирование: Юнит-тесты запускаются через pytest tests/ -v. Проверяют целостность исходного кода, наличие иконок и корректность build.spec.
GitHub Actions:
ci.yml — запускает тесты при каждом push/PR.
build-exe.yml — при создании тега формата v* (например, v9.6) автоматически собирает .exe файл через PyInstaller и создает GitHub Release.
Примечания и известные ограничения
Все операции выполняются от имени пользователя, указанного в Excel-файле. Для критических операций на ALT_SP требуется корректный пароль su.
Используется paramiko.AutoAddPolicy() (ключи хостов не проверяются строго) — используйте только в доверенной сети.
При обновлении конфигурации, если описание и размер локального и удаленного файлов совпадают, обновление пропускается (штатное поведение для экономии времени).
Операция загрузки файлов автоматически переименовывает существующие файлы, добавляя суффикс .old_ГГГГММДД_ЧЧММСС, что позволяет легко откатить изменения при необходимости.
